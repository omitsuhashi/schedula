# バージョン付き JSON 契約を最適化エンジンの境界にする

利用者は担当配置と勤務計画のアルゴリズムを先に作り、LLM 入力を後から接続することを求めている。
LLM がソルバーコードを生成・実行する構成と比べ、型付きの業務ルールを受け取る
Request → Response を中核に置くことで、LLM なしでも検証・利用でき、入力経路に依存しない意味を保てる。
その代わり、新しい業務ルールは契約・モデル・独立検証器を拡張してから受け入れ、
未知の条件を自由記述から自動実行しない。

採用元は[元チャットと ZIP](../sources.md)。具体的な境界は[設計方針](../design-policy.md)に記す。
