# 元の需要を保った未完成の計画を契約0.3で返す

必要人数の不足で全出力が失われると、埋められた配置を使って調整できない。
契約0.3では元の需要を保持したまま不足を最優先で最小化し、需要以外の必須条件を守った
未完成の計画を `PARTIAL` として返す。不足と最適性を別々に表し、希望や勤務量のために不足を増やさない。

[ADR-0001](0001-json-first-engine.md)の版付きJSON境界と
[ADR-0002](0002-joint-roster-optimization.md)の勤務候補・担当配置の同時最適化を維持する。
[ADR-0003](0003-extended-roster-contract.md)の「元条件の正式な解と許可された条件変更案を分ける」
判断に、元の必要人数を変更しない未完成の計画を追加する。人数を減らした入力で成功扱いにする方式や、
検証を無効にして途中の配置を出す方式は採用しない。0.1・0.2の完全充足を求める意味は変えない。

結果の不足一覧は診断から独立させ、省略せず返す。独立検証の成功は需要充足と同義ではなくなるため、
呼び出し側は `status` と不足集計を読む必要がある。基準計画は引き続き完全な計画だけを受理する。
2026-10-07の利用者による計画承認と [Issue #35](https://github.com/omitsuhashi/schedula/issues/35)に基づく。
フィールド・証明範囲・段階的な導入境界は[契約0.3](../io-contract-partial.md)に定める。
