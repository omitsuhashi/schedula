# 継続計画の契約案

[#67](https://github.com/omitsuhashi/schedula/issues/67)で設計し、PR #73で採用した仕様。
実績・確定勤務・期間集計は[#74](https://github.com/omitsuhashi/schedula/issues/74)で契約0.6へ実装した。
利用方法は[契約0.6](../io-contract-continuity.md)。重複期間の基準比較と固定再計画は#75で未実装。
共通方針・採番・採用前の判断は[設計一覧](../planning-extensions.md)を参照する。
初回は `roster` のみ。計画期間の両端は従来通りローカル日付の00:00とする。

## 期間と事実を分離する

計画期間を `W = [S, E)`、履歴と確定勤務を読む区間を `C = [H, F)` とする。
`H <= S < E <= F`、H/Fも同じタイムゾーンの00:00。
新しい `continuity` を省略した入力には、従来の計画前履歴と期間内候補の規則を使う。
指定時は全従業員について次を渡し、`employees[].history` との併記を拒否する。

| 新項目 | 必須性と意味 |
| --- | --- |
| `continuity.context_window` | 必須。H/Fの `start` / `end`。Wを包含する |
| `continuity.employees` | 必須。登録従業員と同じ集合、重複不可 |
| 各要素の `employee_id` | 必須、登録従業員を参照 |
| `before_context` | 必須。既存historyと同じ3項目をH直前について宣言。終了はH以下、勤務日はHより前 |
| `past_complete` | 必須、`true` のみ。HからSまで、勤務なしも含めて実績を確認した宣言 |
| `actual_shifts` | 必須配列。H以降に開始してS以下に終了した全確定実績。空配列は勤務なしを明示 |
| `commitments_complete` | 必須、`true` のみ。C内の既知の確定勤務をすべて入力した宣言 |
| `committed_shifts` | 必須配列。Sより後に終了する確定勤務。Sをまたぐ勤務、W内、E以降の勤務を含む |

各実績・確定勤務は `id`、`segments`（既存の1〜4区間と休憩）を持つ。
従業員は親要素から決まり、勤務日は最初の開始から導出する。
Sをまたぐ勤務は `committed_shifts` だけに全区間を一度記録する。
そのSより前の部分も `past_complete` の確認対象で、別の実績へ複製しない。
Hをまたぐ勤務があるならHを前のローカル日付へ広げ、全区間を入れる。
H以前の最終勤務は `before_context` のみとし、実績配列へ二重に入れない。

Fより先の未入力勤務への休息・連勤は保証しない。
`commitments_complete` は既知の確定勤務の網羅性の宣言であり、未確定の将来勤務を予測しない。
未来の配列の空白は、この求解に含む選択勤務と確定勤務以外に勤務を仮定しないという意味で、
恒久的な勤務禁止にはしない。将来別の計画を作る側が今回の勤務を引き継ぐ。
確認フラグは情報の真正性をエンジンが証明した意味にはならない。

## 候補と出力

自由に選ぶ候補は最初の開始がW内、全区間がC内であることを必須とし、Eを越える終了を許す。
Sより前から始まる勤務は新規選択せず、確定勤務としてだけ取り込む。
テンプレートは開始日がW内のものだけ展開し、Cや勤務可能時間を外れるものを従来通り除く。
明示候補は除かず入力エラーにする。確定勤務は候補集合から消えても解除しない。

勤務可能時間は新版の `continuity` 使用時だけC内へ拡張できる。
新規候補とS以降の確定勤務部分について、休憩を含む各勤務区間全体が勤務可能時間内か検証する。
S以前の確定実績を現在の技能・勤務可能時間で再認定しない。
確定勤務と新しい勤務可能時間の矛盾は、構造が正しければ `INFEASIBLE`。
履歴を削除したり勤務可能時間を広げたりして通過させない。

`solution.shifts` はWと外側区間が交差する選択勤務と確定勤務を全区間のまま返す。
選択勤務は既存の `candidate_id`、確定勤務は新しい `committed_shift_id` を持ち、両者は排他的。
分割勤務の間隔だけがWに重なる場合も全区間を返し、W内の勤務量は0となる。
W外だけの確定勤務は解に複製せず、Requestから検証する。
`assignments`・`shortages` はW内に限定する。確定勤務は勤務状態を固定し、担当役割は自動固定しない。
役割担当を保持する場合は基準計画の固定を指定する。
`continuity_summary` にC、W、従業員ごとの `historical_minutes`（C∩過去）、
`planned_minutes`（W）、`outside_planning_minutes`（E以降）、参照した確定勤務IDを返す。
過去部分・W部分・未来部分の合計が各勤務の全勤務分数と一致しなければ検証失敗とする。

## 区間投影と必須条件

勤務の実区間を `T = union(segments) - union(breaks)` とする。
評価区間Iの勤務分数は `minutes(T ∩ I)`。待機を含み、休憩と分割間の非勤務を含めない。
すべて半開区間かつUTC上の実経過分数で計算し、勤務日への全量帰属は行わない。
区間を切るのは集計時のみ。勤務の同一性、休憩、休息は元の区間を使う。

- `scheduled_minutes`、`max_scheduled_minutes`、既存fairness、選好、費用はW内だけを数える。
- `scheduled_minutes_bounds.interval` はcontinuity使用時だけC内を許す。
  過去実績、確定勤務、新規選択勤務のI内勤務分数を足す。過去と未来の定数も含む。
  過去を含むIはH以降でなければ拒否し、履歴要約だけから勤務量を推定しない。
- 勤務日は最初の開始のローカル日付。1人・勤務日最大1勤務と外側区間の非重複を、実績・確定・候補の全体に適用する。
- 休息は前の勤務の最終終了から次の勤務の最初の開始まで。分割間の非勤務を勤務間休息に置換しない。
  `before_context.last_shift_end`、実績、確定勤務、選択勤務を時刻順に接続する。
- 連勤はH直前の連勤数から勤務日を日単位でたどる。明け日に新しい勤務開始がなければ勤務日にしない。
  E以降の確定勤務までたどり、末日の選択による将来の上限超過も検出する。
- 現在の休息・連勤ルールで過去だけの違反を遡及判定しない。
  S以降に勤務が続く組・連勤区間を検査する。明示した期間上下限は指定I全体へ適用する。
- 現在の需要・担当資格・担当時間上限・担当切替はW内だけに適用する。
  過去の担当役割を要求するルールは本案に追加しない。

日時は分単位。新規候補・確定勤務のW内の全状態遷移はWの粒度に揃える。
履歴とW外部分は整数分で保持し、現在の粗い枠へ丸めない。
期間上下限のW内端点も粒度に揃える。DSTでは明示オフセットを使用し、
テンプレートの曖昧・不存在の開始時刻を拒否する既存動作を維持する。

## 拒否と不可能性を区別する

| 入力・状況 | 結果 |
| --- | --- |
| 従業員行・確認フラグ・アンカー欠落、Hより前の集計要求 | `INVALID_INPUT` / `INCOMPLETE_HISTORY` |
| 実績・確定のID重複、同一人物の事実の外側区間重複、同一勤務日の重複 | `INVALID_INPUT` / `CONFLICTING_CONTINUITY`。内容が同じでも黙って併合しない |
| Sを越える実績をactualへ記録、C外の確定勤務、アンカーと実績の時間矛盾 | `INVALID_INPUT` / `INVALID_CONTINUITY_INTERVAL` |
| 確定勤務の原区間と基準から固定した状態が一致しない | 入力記録自体の同一IDの矛盾なら `INVALID_INPUT`。別の有効な必須条件同士の衝突なら `INFEASIBLE` |
| 履歴を踏まえると新しい上限・休息・連勤・未来固定を満たせない | `INFEASIBLE`。需要不足以外の条件は緩和しない |
| 条件を守る計画はあるが需要だけ不足 | `PARTIAL`。不足はW内の元需要との差 |

実績確認がtrueでも、供給元が勤務を隠したことまでは検出できない。
IDと絶対区間の整合、網羅性宣言の有無、与えられた事実同士の矛盾を検証範囲とする。

## 基準計画と最小の公開Interface

`make_baseline(request, solution, plan_id)` の引数は増やさない。
新版にも対応し、元のW・C・実績・確定勤務・候補・業務条件をそのまま保持して再検証する。
既存の比較用入力除去と `source_fixed_states` への投影は継続する。
新Wへの切り出しは次の `solve` / `verify` の基準処理が行い、保存済み元Requestを書き換えない。

旧Wと新Wの重複 `O` が比較範囲。同じタイムゾーン・粒度を必須とする。
重複なしで基準を指定する入力、粒度変更、タイムゾーン変更は `BASELINE_WINDOW_MISMATCH`。
`fixed_parts` の指定区間はO内のみ。`preserve_assigned` はO内の旧非空担当枠だけを固定する。
明示固定・自動固定とも過去の区間を新Wへ延長しない。

`plan_changes` はO内の従業員ID和集合について勤務状態と役割状態の差を各1と数える。
既存の `slot_components` を保持する。Wから外れた日や新たに追加した日の空欄は変更に数えない。
`change_summary` に `comparison_interval` と `slot_minutes` を追加する。
削除された従業員・役割を含む固定は従来通り成立不能、非固定部分は差として数える。
`rebuild` は比較固定だけを外し、業務事実である `continuity.committed_shifts` は保持する。

実績を作る公開変換は追加しない。計画の解から勤務した事実は判断できないためである。
実績は勤怠等の利用側が確認して作り、将来の確定勤務も利用者の確定操作で明示的に渡す。
担当済み枠だけの自動固定と、勤務全体の確定を混同しない。

## 入力例と数値の期待値

以下は差分を説明する架空の入力表。月末・週途中は契約0.6の実行例として用意した。
1日ずつずらす再計画は#75の未実装範囲。
特記なき日時は2026年、Asia/Tokyo、粒度30分。必要技能は全員が保有し、
勤務可能時間は記載勤務を包含する。需要は指定箇所だけ、他は0。
休息条件の数値は試験用の値である。

### 月末の夜勤

Wは11月1日00:00〜2日00:00、Cは10月31日00:00〜11月3日00:00。
Aliceのアンカーは勤務なし、両確認はtrue、actualは空。
確定勤務Nは10月31日22:00〜11月1日06:00、休憩は11月1日02:00〜03:00。
未来の確定勤務Fは11月2日08:00〜09:00。`min_rest_minutes=660`、連勤上限2。
需要は11月1日00:00〜02:00、03:00〜06:00、各1人。

| 集計・条件 | 期待値 |
| --- | --- |
| Nの全勤務量 | 480−60 = 420分、勤務日は10月31日 |
| Nの過去 / W | 120 / 300分。Nを二回数えない |
| FのW外勤務量 | 60分、需要集計には含めない |
| N→次候補17:00〜21:00の休息 | 660分、許容 |
| 同候補→Fの休息 | 660分、許容。終了21:30の候補では630分で選択不可 |
| 連勤 | N・11月1日候補・Fを選ぶと3日で上限違反。NとFだけなら途中が非勤務日 |
| 固定 / 変更 | N全体を確定、担当は新求解。基準なしなので `change_summary=null` |

勤務量目的を置けば追加の待機候補を選ばず、W内勤務300分・不足0。
Nの原区間・休憩を出力し、00:00で切った勤務へ書き換えない。

### 週途中からの計画

Wは10月7日00:00〜12日00:00、Cは10月5日00:00〜12日00:00。
Aliceの実績は5日・6日の09:00〜17:00、各480分。H以前は勤務なし。
週区間Cの `scheduled_minutes_bounds` は上限2400分、連勤上限5、休息下限660分。
7〜10日に各09:00〜17:00の候補と1人需要がある。目的は勤務量、選好なし。

過去960分なので残りは1440分。7〜9日の3候補を選ぶ解は週2400分、W1440分、
6日17:00→7日09:00の休息960分、5連勤で有効。10日は不足480人分となる。
別の3日を選ぶ同率解も許容し、特定日を必ず選ぶとは主張しない。
4日全部なら2880分かつ6連勤で無効。固定なし・基準なしで変更量はnull。
6日の実績が未確認なら、480分と推測せず入力を拒否する。

### 1日ずつずらす再計画

旧Wは10月5日〜8日、新Wは6日〜9日。旧解はAliceの5・6・7日09:00〜10:00勤務・担当。
新しいcontinuityには5日の実績60分を置く。新しい需要は6・7・8日の同時間、各1人。
`preserve_assigned` は6・7日の計4枠を固定する。8日をAliceが担当すると新W勤務180分、
過去60分、日間休息1380分、4連勤。連勤上限4なら有効。
Oは6日〜8日で、固定4枠は変わらず変更量0。5日の削除と8日の追加を変更に数えない。

`rebuild` で7日の勤務と担当だけをBobへ移すと、7日2枠×Alice/Bob2人で勤務変更4、
役割変更4、合計8。勤務をAliceに残して役割を外しBobを追加する案とは区別する。
6日の1枠だけを同じ方法で交代すれば勤務変更2・役割変更2、合計4。
両方の計画の新W総勤務量は180分。新Wを15分粒度にする入力は初回案では拒否する。

## 境界の受け入れ試験

| 試験 | 期待 |
| --- | --- |
| 10月31日23:00〜11月1日01:00と03:00〜05:00の分割勤務、休憩なし | 全240分、旧月60分・新月180分。01:00〜03:00は非勤務、休息の終端は05:00 |
| Europe/Berlin、2026-10-25 01:00+02:00〜04:00+01:00、休憩02:00+02:00〜02:30+02:00 | 実経過240−30=210分。重複する時計表示を同一瞬間としない |
| 履歴アンカーと最初の実績の外側区間の重複、実績と確定の重複 | 入力エラー |
| 確定勤務・休憩・勤務日・参照IDを改ざんした出力 | `verify` の不正計画。求解結果なら `INTERNAL_ERROR` / 解なし |
| 同じ小規模勤務列を通しで検証し、各区切りの実績と未来固定を渡して分割検証 | 各期間の勤務・不足の合計と通し集計が一致し、境界の休息・連勤違反を同じく検出 |

分割時に未来を固定しない独立最適化が通し最適化と同じ解・目的値になるとは要求しない。
通し解を引き継いだ検証の同値性と、各部分問題の全探索での最適値一致を別々に試験する。

## 実装順

| 順序 | 変更・検証 |
| --- | --- |
| 契約と意味検証 | 新版だけにcontinuity・勤務参照・集計を追加。履歴欠落、事実重複、粒度、整数上限を先に拒否 |
| 候補とモデル | 元の絶対区間を保持しWへのcoverageを作る。確定勤務を定数として休息・連勤・勤務量へ接続 |
| 独立検証 | 生のsegmentsから投影を再計算。モデルのcoverageや係数を参照せず、過去と未来の条件も照合 |
| 基準と移行 | 旧基準の再検証、Oへの比較・固定投影、スナップショット往復。旧版の期間不一致拒否は保持 |
| 結合 | 上記3例、分割・DST・未来固定・全探索、#68の背景分類、#69の費用、#70の履歴評価 |

既存 [ADR-0003](../adr/0003-extended-roster-contract.md)の期間内限定を新版で再検討する理由は、
夜勤と勤務量を切らずに期間をずらすためである。実装時に[ADR-0006](../adr/0006-continuity-original-intervals.md)へ記録した。旧ADRの事実は変更しない。
