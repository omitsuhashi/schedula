# 夜勤と休日の勤務分数の偏りを評価する契約案

[#70](https://github.com/omitsuhashi/schedula/issues/70)の採用仕様。
計画内の評価を[#78](https://github.com/omitsuhashi/schedula/issues/78)で[契約0.9](../io-contract-roster-metrics.md)へ実装した。
履歴を含む評価は[#79](https://github.com/omitsuhashi/schedula/issues/79)で[契約0.10](../io-contract-duty-continuity.md)へ実装した。
利用側が指定した区間に重なる勤務分数を集計し、従業員ごとの明示目標との差を評価する。
既存の `fairness_deviation_minutes` は計画全体の勤務量の尺度として維持する。

## 尺度と入力

初回は勤務回数ではなく実経過分数を採用する。
夜勤と判定する最低重複時間・分割勤務の回数・日付の帰属を追加せず、
短い夜勤と長い夜勤の負担を入力した区間内の勤務分数で区別するためである。
単純な人数均等化・契約比率での正規化・法定休日の判定は行わない。

新しい `duty_balance` は1〜20件の評価定義を持つ配列とする。
20件は初回の入力上限案で、通常の夜勤・休日以外の区分を無制限に増やさない。
各定義は一意な `id`、`label`、`evaluation_period`、1〜1000件の `intervals`、
1〜250人の一意な `employee_targets`（`employee_id` / `target_minutes`）を持つ。
labelは表示用で分岐に使用しない。夜勤/休日という予約語で処理を切り替えない。

```json
{
  "duty_balance": [{
    "id": "night",
    "label": "夜勤",
    "evaluation_period": {
      "start": "2026-10-07T00:00:00+09:00",
      "end": "2026-10-09T00:00:00+09:00"
    },
    "intervals": [
      {"start": "2026-10-07T22:00:00+09:00", "end": "2026-10-08T02:00:00+09:00"},
      {"start": "2026-10-08T22:00:00+09:00", "end": "2026-10-09T00:00:00+09:00"}
    ],
    "employee_targets": [
      {"employee_id": "alice", "target_minutes": 180},
      {"employee_id": "bob", "target_minutes": 180}
    ]
  }],
  "objectives": [{"id": "night_balance", "metric": "duty_deviation_minutes", "duty_id": "night"}]
}
```

このJSONは現在の契約0.15の部分例。完全な実行入力は[夜勤評価例](../../examples/duty_balance.json)を参照する。
導入時の契約0.9/0.10の判断・測定は履歴として保持する。
評価期間は初回ではW内の正の半開区間。各intervalはその評価期間内に収め、粒度へ揃える。
intervalの和集合を集計し、同一評価内の重複・隣接・同一区間の再掲は併合して二重計上しない。
異なる評価間の重複は許し、それぞれ別目的として評価する。
例として休日の夜勤は `night` と `holiday` の両方に計上できる。

対象は `employee_targets` に列挙した従業員だけ。未指定者は対象外であって目標0ではない。
明示目標0は勤務0分を望むという意味で、有効なソフト目標。
targetは0〜10,000,000の整数。未知ID・重複ID・null・負数・boolは拒否する。
全対象者が未指定の定義は拒否する。対象外者へ偏りを移す可能性は利用側が対象集合で管理する。
国・地域の祝日や夜勤区間を推測せず、休日の暦は利用側で絶対日時へ展開する。

## 目的の識別と計算

`duty_balance` の各定義と、metricが `duty_deviation_minutes` の目的を `duty_id` で1対1対応させる。
評価だけ定義・目的だけ指定、同一定義への複数目的、未知参照を拒否する。
他metricに `duty_id` を付ける入力も拒否する。
現在の `normalize` はmetricの重複を禁じるため、新版に限りこのmetricは
`(metric, duty_id)` を一意キーとする。他metricの重複禁止は維持する。
目的の `id` は引き続き全体で一意。夜勤と休日は配列の順に優先し、巨大な重みで足さない。
目的数上限は採用版で通常metric数と20定義を格納できるよう整合させ、旧版は変更しない。

評価区間群の和集合をU、従業員eの休憩を除く勤務区間群をTとすると、
`actual_minutes[e] = minutes(T[e] ∩ U)`、
`deviation[e] = abs(actual_minutes[e] - target_minutes[e])`、目的は対象者の偏差の和。
待機を含み、休憩・分割間の非勤務を除く。
勤務日の帰属は勤務自体の識別・連勤に使うだけで、夜勤開始日に全量を寄せない。
日付・月境界の集計は絶対区間の交差による。

候補係数と偏差の上界をモデル構築前にPython整数で計算し、既存の `2**60-1` の安全域を守る。
目標達成不能でも入力を拒否せず、実現できる最小偏差を返す。
候補がない人の目標240分なら実績0・偏差240分。
目標合計を総勤務量へ自動補正せず、必要人数・必須上限・固定も緩和しない。

## 優先順と結果

不足と#66の不足評価の後、`objectives` の指定順で最適化する。
希望勤務日時は既存の `preference_penalty`、勤務費用は `scheduled_cost`、
総勤務量の公平性は既存 `fairness_deviation_minutes` として別々に比較できる。
`preserve_assigned` と明示固定は必須で、偏りを減らすために解除しない。
`rebuild` は比較用固定を外すが、#67の確定勤務は保持する。

`duty_balance_summary` は対象外ならnull、対象なら定義順の配列。
各要素は `duty_id`、`label`、`evaluation_period`、正規化した `intervals`、
`unit: "minutes"`、`scale: "absolute_deviation"`、`normalized: false`、
`total_deviation_minutes`、`employees`（ID、target、actual、deviation）を持つ。
Responseの各目的にも `duty_id` を返し、値が対応集計の合計と一致することを検査する。
勤務0の対象者も省略しない。実装後の公開 `verify` も同じ集計を返すが最適性はfalse。

「偏りが小さい」は指定した対象・区間・目標についてだけの説明。
担当回数や公正な配分一般を保証する表現にはしない。
待機も計上するため、目標を満たすだけの待機勤務を選ぶことがある。
その抑制が必要なら `scheduled_minutes` と偏差の優先順を利用者が明示する。

## 数値例

Asia/Tokyo、粒度30分、Alice/Bobは同じ担当資格。10月7日・8日の各日に
昼10:00〜14:00、夜20:00〜24:00の4時間勤務が各1人必要。
各人に各日の昼/夜の候補があり、1人1勤務日の規則で両方は選べない。
休憩なし、休息下限600分、両日勤務可能。各人の総勤務量は480分となる。
夜の2区間を評価対象として、各人の夜勤目標は240分とする。

| 計画 | 総勤務量 Alice/Bob | 夜勤分数 Alice/Bob | 夜勤偏差合計 |
| --- | --- | --- | --- |
| Aliceが両夜、Bobが両昼 | 480 / 480 | 480 / 0 | 480 |
| Aliceが7日夜・8日昼、Bobが7日昼・8日夜 | 480 / 480 | 240 / 240 | 0 |

どちらも最短休息600分を満たす。既存fairnessの各目標480分では両案とも0。
新しい夜勤目的で交代する案を選べる。夜勤目標0のAliceが固定で240分勤務するなら偏差240、
固定を解除せず未達として返す。

Aliceに8日の昼10:00〜14:00の `avoid_work` 単価1を置く。
夜勤偏差→希望では交代案の偏差0を優先でき、
希望→夜勤偏差ではAliceを両夜にして選好0・偏差480となる解を許す。
ただし交代の反対向きでも希望0を達成できるため、比較試験では7日Alice夜・Bob昼を固定する。
その固定を明示した上で、前者は選好240・偏差0、後者は選好0・偏差480となる。

費用→偏差なら同じ不足の中で低費用を先に、偏差→費用なら偏差を先に最小化する。
総勤務量が同じで各人の単価が一定なら両案の費用も同じなので、費用差があると推測しない。
`preserve_assigned` で元の両夜を固定すれば偏差480のまま。
`plan_changes` を偏差より先に置いても同じ基準を維持し得る。

## 境界と履歴

| 対象 | 期待する意味・検証 |
| --- | --- |
| 夜22:00〜06:00、休憩02:00〜03:00 | 夜勤420分。00:00で分けるなら120+300分 |
| 分割22:00〜24:00、02:00〜04:00 | 夜勤240分。00:00〜02:00を含めない |
| 評価区間22:00〜02:00と00:00〜04:00、勤務22:00〜04:00 | 和集合で360分。480分と重複計上しない |
| 休日と夜勤が同じ勤務に重なる | 各定義内で一度ずつ計上。両目的の優先順は明示 |
| Berlinの2026-10-25 01:00+02:00〜04:00+01:00 | 240分。休憩30分なら210分、時計表示差の180分を使わない |
| 目標0 / 対象外 / 達成不能 | 0目標には実勤務分だけ偏差。対象外は集計に含めない。達成不能は有効なソフト未達 |

初回の計画内評価はH以前の履歴を読み込まない。
過去を含む評価は親で予約した契約0.10へ導入した。
0.10ではevaluation_periodをC内へ広げ、U∩過去の確定実績を定数、
U∩Wの勤務を選択値、U∩未来の確定・選択勤務をその計画の値として集計する。
同一勤務をSで分割集計し、元区間を二重登録しない。

例として月の過去夜勤がAlice240分・Bob0分、残り夜勤需要240分、各人目標240分なら、
Bobに残りを割り当てて合計240/240・偏差0。Aliceを選べば480/0・偏差480。
過去が未確認なら0として計算せず `INCOMPLETE_HISTORY`。
新規入社も確認済みの勤務なしとして明示し、自動0補完しない。
既存fairnessの履歴を含まない意味は、この拡張でも変更しない。

## 実装順と受け入れ

| 単位 | 変更・試験 |
| --- | --- |
| Schemaと意味検証 | 区間・対象・目標・目的の1対1、metricとduty_idの一意性、目的上限、未知項目、旧版回帰 |
| 候補係数と目的 | Uの和集合から係数を計算して絶対偏差を作る。小規模候補の全探索で目的順ごとの最適値を照合 |
| 独立集計と出力 | 元の勤務区間と入力区間から再計算。モデルの正規化区間・係数を流用せず、改ざんした勤務・対象・集計を検出 |
| 結合 | 昼夜交代例、固定・希望との競合、費用・不足の優先、待機、DST、区間重複・配列順の不変性 |
| 履歴拡張 | #79で契約0.10へ実装。通し/分割集計、履歴欠落、実績と確定の二重計上拒否 |

夜勤回数や必須の夜勤上限が必要になった場合は別要件とする。
前者は勤務の夜勤成立条件、後者は制約としての違反検出と不可能性診断を追加してから導入する。
