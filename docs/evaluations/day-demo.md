# 勤務日数・完全休日の2主題の技術確認

2026-10-10、[#129](https://github.com/omitsuhashi/schedula/issues/129) の2主題を追加した。基点mainは `799a93345fd58b1016e4be7c17765ecd876163c5`。入力は0.15・Asia/Tokyo・固定した架空条件。
オーナーの後続指示によりこの単位は #126 の完了を待たず実装する。対象利用者による理解度評価は未完了として残す。

## 実計算と公開の独立検証

初期は10月5〜10日（終端を含まない）で勤務3日・占有4日・完全休日1日。
確認済み実績は10月4日22時〜5日0時、確定勤務は5日22時〜6日2時。
今回の有限候補は7日の分割勤務、8日22時〜9日0時の勤務、9日の需要のない勤務である。
分割勤務は1勤務日。夜勤明けの6日は勤務開始なし・占有ありで、完全休日ではない。0時終了は9日を占有しない。
実績と確定勤務と今回の採用を一度ずつ数える。評価開始を4日へ広げると実績も加わり、勤務4日・占有5日・完全休日1日となる。
9日だけの評価では勤務0日・占有0日・完全休日1日。計画終端を越える評価は文脈期間内でも `INVALID_DAY_COUNT_INTERVAL` で拒否する。

| 変更 | 結果 |
| --- | --- |
| 勤務日上限2日／完全休日下限2日 | 勤務2日・占有3日・完全休日2日、不足60人分 |
| 勤務日下限4日／完全休日上限0日 | 需要のない9日も勤務。勤務4日・占有5日・完全休日0日、不足0人分 |
| 勤務日下限5日／完全休日下限4日 | 候補・確定勤務の範囲で不成立。`INFEASIBLE`、解と日数指標なし |
| 下限3日・上限2日 | `INVALID_INPUT`、条件を緩めない |
| 過去を含む評価で履歴確認を解除 | `INCOMPLETE_HISTORY` を伴う `INVALID_INPUT`、未確認を休日と推定しない |

2主題の初期・変更・復元16段階を実solveで確認する。解のある12段階は公開verifyで独立検証する。
公開verifyは有効性と不足を確認し、最適性・不足最小性の証明とは分ける。名前・配列順・全セルを期待値にせず、日数・上下限・不足を検査する。
`tests/test_day_demo_lessons.py` は原勤務・実績・確定勤務から別の日付集計でも照合する。
