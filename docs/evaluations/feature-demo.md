## HTTPと描画までの時間

`featureMeasurements`はPOST開始からHTTP往復、応答検査、DOM更新、2回のrequestAnimationFrameまでを測る。
教材GET・ページ読込・依存導入・OSキャッシュ消去は含めない。初期計算と継続再計算を別に記録する。
探索予算は教材の5秒、worker数はサーバーの既存設定2。総応答時間の保証とは分ける。
各教材の変更再計算を3回繰り返し、結果は`test-results/feature-measurements.json`と
`test-results/playground-browser.json`に出力する。2秒以内は同等環境の暫定目安であり、
共有CIの負荷に対する保証や固定のタイミングassertにはしない。
2026-10-10にサーバーを新規起動する3回の実行で45件を測定した。
初期6件は需要137.1〜142.5ms、連勤278.7〜294.4ms、全45件の最大294.4msで暫定目安を満たした。
各実行では先行2教材の全ガイドと自由編集、同じ値での再計算3回を確認し、復元は保存した初期結果へ戻した。
[結果JSON](https://github.com/omitsuhashi/schedula/blob/4ebf0bda0c0695ff548f5300373456e894e4133f/docs/evaluations/results/feature-demo-20261010.json)にChromium 151.0.7922.34、各応答のstats/solver、
source baseと測定したファイルのSHA-256を保存した。固定commitからの初期入力・候補・目的の再検証とは分ける。
同一ホストで全体回帰も稼働していた測定であり、無負荷の性能保証とは扱わない。
後続の#126ではこの実測と実際の待ち時間評価を照合する。

```sh
uv sync --locked --extra cp-sat
uv run --no-sync pytest -q tests/test_demo_lessons.py tests/test_playground_server.py

```

## 夜勤回数と手修正検証の追加確認

2026-10-10、技術的に完成した#119のmain `ced7c9addd8f3337408eaa036d3958b76f53789a`を基点に追加した。
エンジンは変更せず、同じ固定依存を使う。教材の6段階＋公開verifyの5段階＋INVALID_INPUTを、
それぞれ新Pythonプロセス3回、計36件で確認した。OSキャッシュは消さず、求解は既定2 workers・予算5秒。
求解結果は元Requestに対する公開verifyで再検証し、入力・実績・候補・固定勤務が変わらないことを教材テストでも確認した。
生記録`docs/evaluations/results/early-feature-demo-20261010.json`へ環境、source base、lockと教材のSHA-256、
実Responseと公開verify、処理時間、プロセス全体時間を保存する。HTTP/描画時間とは分ける。

| 主題 | 新プロセス最大（秒） | API処理＋求解後の公開verify最大（秒） |
| --- | ---: | ---: |
| 夜勤回数 | 0.4897 | 0.3707 |
| 一枠の手修正検証 | 0.1641 | 0.0848 |

夜勤回数は目標だけ1/1→2/0の実回数変化、明示0/0の偏差2回と需要充足、未指定者の対象除外、
分類区間と閾値の変更で勤務を残したまま実回数0、復元を確認する。同率解の個人名や全セル一致は固定しない。
手修正はVALID→INVALID_PLAN→PARTIAL→VALID→復元と、実Request不備のINVALID_INPUTを公開APIで検査する。
INVALID_PLANは無効な編集案を位置付きで表示し、採用操作を設けず、再編集・再検証を継続する。
公開verifyは最適性・不足最小性を付与せず、別の求解Responseの形式を強制しない。

Chromiumでは上記ガイド、自由フォームの未指定/0、両者未指定の送信抑止、キーボード、390px幅、
表スクロール、編集後の失効、HTTP BUSYからの復帰、遅い検証応答の排除を確認する。
証明フラグ・検証状態・実行識別子・求解状態へ改変した応答を拒否する境界試験も含む。
HTTP/描画実測は同じ`featureMeasurements`で記録し、求解と公開verifyを別の主題として保存する。
ローカルサーバー1回起動で夜勤10件・verify 8件を測定し、最大はそれぞれ49.3ms・56.8msだった。
Chromium 151.0.7922.34、UTC、1440px/390px、同じホストでPython全体回帰も稼働していた条件を生記録へ保存した。
先頭の画面初回と継続操作を`run_kind`で区別する。`initial`は初期条件との一致で、元の条件に直した継続操作も含む。
教材GET・ページ読込は含まず、共有CIや実利用者の待ち時間の保証にはしない。
HTTPでは全4状態、求解を呼ばないこと、厳密JSON・Host/Origin・2 MiB・表示上限・共有ロックを維持する。
