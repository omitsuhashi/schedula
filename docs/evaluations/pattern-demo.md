# 勤務パターンの4主題の技術確認

2026-10-10、[#130](https://github.com/omitsuhashi/schedula/issues/130) の4主題を追加した。基点mainは `2c4e301d18f0b41c118341a0321d9c7e13d0a1c9`。入力は0.15、固定した架空のA・Asia/Tokyo・30分粒度。
オーナーの「続きをお願いします」に基づき、この単位は #126 の完了を待たず実装する。対象利用者による理解度評価は未完了として維持する。

## 実計算と公開検証で確定した性質

| 教材 | 初期と変更の性質 |
| --- | --- |
| 連続休日 | 評価5〜9日、連続休日下限1日・完全休日数下限1日（別条件）。不足0人分・評価内休日1日。連続下限2日では6・7日を休み不足60人分。3日では8日から確認範囲終端11日までの4連休を数え、不足60人分 |
| 休日の存在 | 連続下限2日のまま別条件の休日数下限を0日へ変更すると、需要のない6日も勤務し、評価内完全休日0日・不足0人分。連続休日の条件だけでは休日を強制しない |
| 勤務後の休み | 5日22時〜6日06時の勤務後、2完全休日なら次勤務は9日00時以降。不足30人分。1日なら8日00時で充足、3日なら10日00時で不足90人分 |
| 終端と分類 | 原勤務を6日00時終了へ変更すると2休日の境界は8日00時。分類区間の和集合と休憩を除く原勤務の重なりは初期450分。閾値480分では分類されず、この休み義務の対象にならない |
| 禁止する並び | 5日の遅番→2日差の7日早番を禁止し、不足60人分。間に6日の必須勤務があっても禁止。日差1・3や早番閾値90分では禁止の組なし・不足0人分。評価開始6日でも5日開始の遅番が7日禁止へ影響する |
| 日付群 | 10・11日と17・18日の二群で、初期は二群・群内3日付に勤務。上限1群では同じ第1週末の土日を一群と数え、第2週末に60人分不足。四日を一群にまとめると上限1群で充足 |
| 群と0時終了 | 9日の夜勤は10日に触れて第1群へ寄与。終端10日00時では10日を占有せず、勤務する群数は二群のまま群内の勤務日付は2日になる |

26段階を実solveで確認する。解のある22段階は元Requestと公開verifyでも検査する。公開verifyは有効性と不足を確認するが、最適性・不足最小性の証明とは分ける。
連続休日4日・禁止日差5日は必要な右余白がW外となり、Cに未来があっても `INCOMPLETE_HISTORY` で拒否する。解なしとは分ける。
夜勤後の不足も必須最低人数1人とすると不成立。日群上限0群も必須夜勤と矛盾して不成立。必須条件を緩めず、解・不足指標を返さない。
`tests/test_pattern_demo_lessons.py` は元入力保持、別の日別占有・休日区間集計、分類の既知分数、禁止日差・原開始日・群数、公開検証の性質を確認する。群間で重複する日付も拒否する。
同率解の個人名・配列順・全勤務表を期待値にしない。休日区間の長さは確認範囲内の値とし、計画外へ延びるかを推定しない。
