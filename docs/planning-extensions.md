## 推奨する仕様

| #68 | 背景条件を固定し、条件グループの削除再求解で十分集合を縮小する | [矛盾の絞り込み](designs/conflict-refinement.md) |
| #69 | 単一通貨・明示倍率の整数分単価から計画内費用を計算する | [勤務費用](designs/scheduled-cost.md) |

共通で、必須条件と元需要を保持し、不足合計人分の最小化をすべての指定目的より先に行う。
#66で追加する需要優先度も、そこで定める不足評価の後に本案の指定目的を置く。
指定目的は `objectives` の配列順で最適化する。上位目的が未証明なら後続を実行しない。
`verify` は有効性と評価値を再計算し、最適性・不足最小性を認定しない。

## 契約版と移行

契約版の採番は [親Issue #58](https://github.com/omitsuhashi/schedula/issues/58)で一元管理する。
本案中のフィールド名は新契約候補で、`0.5`などの未確定版番号を例へ埋め込まない。
#66の版に相乗りするか別版にするかは、#66の確定内容と合わせて親で決める。
一度実装・公開した同一版へ後から意味の異なるフィールドを足さない。

0.1〜0.4のSchema・結果・目的尺度・期間外拒否を維持する。
新項目のない旧Requestはその版のまま実行し、新項目を旧版へ渡したら拒否する。
旧データを自動で新版へ書き換えない。新版の基準計画は対応済みの旧版を元の意味で再検証する。
旧版の `make_baseline` の結果も変更せず、新版の履歴を0補完しない。

## 親Issueで確定する業務上の選択

| 判断 | 推奨値 | 代案と影響 |
| --- | --- | --- |
| 境界を越えて新しい勤務を選べるか | 全区間の勤務可能時間が確認できる候補を許す。元区間を返す | 確定済みの境界勤務だけなら実装は小さいが、月末に新規夜勤を作れない |
| 再計画の粒度変更 | 初回は拒否。同じタイムゾーン・粒度に限定 | 状態が一様な新枠への再投影を別途定義すると対応可能。変更量尺度の比較が増える |
| 実績の完全性 | 全対象者の明示確認を必須にする。欠落は拒否 | 0補完は休息・上限・公平性を誤るため採用しない |
| 費用の単位 | 利用者指定の整数倍率と分単価。期間内の勤務分のみ | 候補総額なら日額等を渡せるが、境界分割時の費用配賦が別途必要 |
| 夜勤休日の偏り | 明示した目標分数への絶対偏差 | 回数や契約比率なら夜勤成立条件・分母・丸めを別途定義する |
| 診断の説明粒度 | ルール1件・需要1件・明示固定1件のグループ | 従業員・時間枠へ分割すると詳しくなるが探索回数と返却量が増える |

採用する推奨値、契約版、実装Issueを親へ反映した後に機能実装へ進む。
本案の受け入れはこの業務選択の確認であり、機能の正しさや実運用性能の確認を代替しない。

## 設計時の検算

[検算スクリプト](designs/check_examples.py)は標準ライブラリで期間・費用・偏差の数値と
小規模の診断縮小を検算する。`--cp-sat` を付けると仮定方式と削除方式を同じ小規模条件で比較する。
これは実装済み機能の受け入れ試験ではなく、仕様例の整合性の確認である。

```sh
python3 docs/designs/check_examples.py
uv run --locked --extra cp-sat python docs/designs/check_examples.py --cp-sat
git diff --check
```

2026-10-07の設計検算では、標準ライブラリの数値・全探索チェックと、
Python 3.14.8 / OR-Tools 9.15.6755でのCP-SAT比較が成功した。
仮定方式はAliceの上下限、削除方式はBobの上下限を十分集合として返し、
両者を全探索で照合した。削除方式は各要素を除くと成立することも確認した。
UNKNOWNの注入では極小性を主張しない。Ruffの検査・整形も成功した。
新しい契約を実行するテスト、実務サイズの性能評価は実装時の作業である。

実装時は旧契約の回帰、各詳細の反例、全探索、改ざん解の独立検証、複数機能の結合を実行する。
性能は既存の `scripts/evaluate.py` に同じ候補集合・予算の入力を追加して測り、
準備・探索・独立検証・診断追加時間を分ける。設計例の成功から実務性能は保証しない。
