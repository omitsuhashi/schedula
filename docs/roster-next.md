# 契約0.2の夜勤・分割勤務

契約0.2の `roster` は、1人・勤務日ごとに最大1候補を選ぶ有限候補方式を維持し、
一つの候補を1〜4個の勤務区間で表す。勤務と担当配置を同じ CP-SAT モデルで決める。
業務上の意味は [入出力契約0.2](io-contract-next.md)、判断は
[ADR-0003](adr/0003-extended-roster-contract.md) を参照する。
従来の契約0.1は [勤務計画の利用手順](roster.md) の形式と日跨ぎ拒否を維持する。

## 実行と例

```sh
uv sync --locked --extra cp-sat
uv run --locked --extra cp-sat python -m shift_schedula solve examples/overnight.json
uv run --locked --extra cp-sat python -m shift_schedula solve examples/split_roster.json
```

ライブラリは `from shift_schedula import solve`、`solve(request)` を使う。
Request の `schema_version` を0.2にし、各候補の `segments` に `interval` と `breaks` を指定する。
返却勤務も `segments` を持ち、最初の区間が開始するローカル日付を `work_day` に返す。
候補IDが同じでも入力区間と返却区間が違う解は独立検証で遮断する。

| 架空入力 | 需要を満たす勤務・担当 | 目的値 |
| --- | --- | --- |
| [overnight.json](../examples/overnight.json) | 10月6日22:00〜7日06:00、23:30〜00:30は休憩。休憩外をAliceが担当。勤務日は6日 | `scheduled_minutes = 420` |
| [split_roster.json](../examples/split_roster.json) | 10月6日09:00〜12:00と17:00〜21:00を一候補として選び、各区間をAliceが担当。12:00〜17:00は非勤務 | `scheduled_minutes = 420` |

正常な小規模例では `OPTIMAL` と検証済み解を返す。探索予算内に最適性を証明できない場合も、
解があれば独立検証を通した `FEASIBLE` として扱う。予算切れの `UNKNOWN` は不可能性の証明ではない。
実行状態と終了コードは契約0.1と共通で、検証済み `OPTIMAL` / `FEASIBLE` は0、それ以外は2。

## 時間と必須条件

- 時間枠・勤務量・休息・分割間隔はオフセット付き日時の実経過時間で計算する。日付の帰属には `planning_window.timezone` を使う。夜勤明けの日に新たな勤務を開始しなければ、その日は連勤に加えない。
- 各勤務区間は時刻順で正の間隔を空ける。隣接・重複・逆順は `INVALID_INPUT`。隣接区間は入力者が一つにまとめる。休憩は各区間の厳密な内側とし、互いに重ならない。
- 勤務量は各区間の長さから休憩を引く。未担当の待機は含み、分割区間間の非勤務は含まない。休憩・非勤務に担当を置かない。
- `min_split_gap_minutes` は同一候補の区間間隔の下限。例の300分は満たすが、330分なら同じ候補は選べず、需要を満たす代替がなければ `INFEASIBLE`。
- `min_rest_minutes` は勤務の最後の終了から次の勤務の最初の開始までに適用する。分割例の660分の休息条件は、同一勤務内の300分の間隔には適用しない。
- 同じ従業員の別勤務は、最初の開始から最後の終了までの外側の区間が重ならない。分割の間に別勤務を挿入できない。勤務日は異なっても重複を許さない。
- 各区間全体は計画期間内・勤務可能時間内に収める。分割間の非勤務まで勤務可能時間を広げる必要はない。期間端を越えた明示候補は切らずに拒否し、必要なら計画期間を広げる。

全員の履歴に `last_shift_end`、`last_work_day`、`consecutive_work_days_before_window` が必要である。
`last_work_day` は開始日の帰属を明示し、終了日から推定しない。空履歴は終了・勤務日をともに
`null`、連勤数を0とする。終了は計画開始以下、勤務日は計画前かつ終了の直前が属する日以前とし、
直前日が勤務日なら正の連勤数、直前日が休日なら0を指定する。
計画開始後に終わる履歴の夜勤は入力エラーとし、前日も含む計画へ広げて表す。
計画後の勤務との休息も確認する場合は、その勤務を含む計画期間にする。

## テンプレートと上限

0.2の `shift_templates.segment_options` は、一候補の形状を並べた配列である。
各形状の区間は最初の出勤からの `offset_minutes`、`duration_minutes` と、
区間開始からの休憩オフセット・長さを持つ。最初の区間のオフセットは0。
対象者×日付×開始時刻×形状の直積を決定的に展開する。
夜勤も同じ形状で生成でき、長さ・オフセットは時計変更を含む実経過分数である。
曖昧なローカル開始時刻・存在しない開始時刻は拒否し、明示候補ではオフセットで一意に表す。

期間外・勤務可能時間外の生成候補は除外するが、不正な区間・休憩・粒度を黙って除外しない。
候補IDには版、テンプレートID・対象者・日付・開始時刻・区間・休憩条件を含む。
ID衝突は入力エラーで、同じ配列集合の並べ替えから同じ候補集合とIDを生成する。
勤務候補件数の上限は撤廃した。明示・生成候補の構造検証と有限候補の意味は維持する。
区間は1候補最大4件、休憩は1区間最大10件。共通の人数・時間枠・モデル規模の上限も維持する。
これらは探索範囲であり、応答時間や現場ルールへの適合の保証ではない。

## 検証

```sh
uv run --locked --extra cp-sat pytest -q tests/test_extended_roster.py tests/test_roster_contract.py tests/test_roster.py tests/test_roster_verification.py
```

夜勤休憩、開始日連勤と履歴、年境界、時計変更、期間外拒否、分割間隔、次勤務との休息、
テンプレートの再現性と候補上限を確認する。元JSONだけから候補部分集合を列挙する小規模全探索で
実行可能性・最小勤務量を比較し、勤務日・区間・休憩を改ざんした解、休憩・分割間の担当を
独立検証器が検出して `INTERNAL_ERROR` / `solution: null` にすることを確認する。
休息・間隔の数値は架空の試験値であり、法令・就業規則の推奨値ではない。
